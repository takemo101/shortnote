# ShortNote を、CLI で操作する

ShortNote は、macOS のメニューバーに常駐する、付箋のようなペイントツール。人が描くキャンバスに、**エージェントが、シェルの CLI で、図形・文字・画像を足せる**（人が入力・ドラッグしている最中でも、壊さずに足せる）。MCP は無い。このスキルは、その CLI の使い方。

```sh
SN=/Applications/ShortNote.app/Contents/MacOS/ShortNote   # 実行ファイル。ビルドしたものなら build/ShortNote.app/Contents/MacOS/ShortNote
```

## どれを使うか

| やりたいこと | コマンド | アプリ |
|---|---|---|
| 画像に注釈して、PNG を作る（まず、これ） | `render` | 要らない。ヘッドレス |
| 人が見ているキャンバスに、注釈を足す | `draw` | 動いていなければ、フォーカスを奪わずに起動する |
| いまのキャンバスの中身を、JSON で読む | `get` | 動いている必要がある |
| いまのキャンバスを PNG で受け取る | `export` | 動いている必要がある |
| 描いたものを全部消す | `clear` | 動いている必要がある |

**試行錯誤は `render` でやる。** `draw` で足したものを、CLI から個別に取り消す手段は無い（人が Cmd+Z で、1 回の `draw` ごとにまとめて戻せる）。`clear` は、**人が描いたものも**消す（人は Cmd+Z で戻せる）。人のキャンバスに足すのは、結果が固まってから。

## 操作の JSON

```json
{"version": 1, "ops": [
  {"op": "rect", "x": 40, "y": 60, "w": 200, "h": 80, "color": "#ff0000", "size": 4},
  {"op": "line", "from": [240, 100], "to": [320, 160], "color": "#ff0000"},
  {"op": "text", "x": 325, "y": 150, "text": "ここを直す", "color": "#ff0000", "fontSize": 20}
]}
```

- **座標は、キャンバスのポイント（pt）。左上が原点、x は右へ、y は下へ増える。小数 OK。** 範囲の外の座標は、エラーにならず、キャンバスの縁に丸められる。結果の `clamped`（丸めた操作の番号）と `skipped`（丸めて大きさがなくなり、足さなかった操作の番号）で分かる。
- `color`：`"#RRGGBB"` か `"#RRGGBBAA"`（既定 `#000000`）。`size`：線の太さ pt、1〜40（既定 4）。

| `op` | 必須 | 任意 | 意味 |
|---|---|---|---|
| `pen` | `points`: `[[x,y],...]`（1〜10000 点） | `color` `size` | 点をつないだ線（フリーハンド、点 1 つは丸い点） |
| `line` | `from` `to`（長さ 1 以上） | `color` `size` | 直線 |
| `ellipse` | `x` `y`（左上）`w` `h`（1 以上） | `color` `size` | 外接する四角に内接する楕円の線 |
| `rect` | `ellipse` と同じ | `color` `size` | 四角の線 |
| `text` | `x` `y`（左上）`text`（1〜10000 文字、`\n` で改行、空白だけは不可） | `color` `fontSize`（8〜200、既定 18） | 文字 |
| `image` | `path` `x` `y`（左上） | `w` `h`（1 以上） | 画像。`w`・`h` を省くと自然な大きさ（キャンバスより大きければ縮小）。片方だけなら縦横比を保つ |

- **知らない `op`・知らない項目・範囲外の値は、すべてエラー**（打ち間違いを、黙って無視しない）。1 つでも不正なら、**何も適用しない**。エラーに、何番目の操作か（`op`、0 始まり）が入る。
- 上限：1 要求 1 MiB、`ops` 1000 個、`image` 20 枚。UTF-8 の JSON だけ。
- `rect`・`ellipse` は線だけで、塗りつぶさない。強調したい所は、枠で囲む。
- 文字は、1 文字の幅が、全角でおよそ `fontSize`、半角でおよそ `fontSize × 0.55`（目安）。位置を決めたら、**必ず、出力を見て確かめる**。
- **矢印の op は無い。`line` 3 本で作る**：本体（しっぽ → 先端）と、先端から出る、矢じりの 2 本。先端を `T`、しっぽを `S`、`u` を `T` から `S` へ向かう単位ベクトル、`L` を矢じりの長さ（20〜25 pt が目安）として、矢じりの端は `T + L·rot(u, +25°)` と `T + L·rot(u, −25°)`。例：しっぽ (600,400)・先端 (310,245)・L=24 → 矢じりの端は (324.4,264.2) と (334,246.3)。
- 線は、図形の縁を中心に、太さの半分ずつ両側へ出る。対象を**囲む**ときは、対象の外側へ `size/2` pt 以上離して置く（対象に重ねたくないとき）。

## 画像に注釈する（`render`）

```sh
$SN render [--size 幅x高さ] [--transparent] <背景の画像 | -> <操作の JSON のファイル | -> -o <出力.png>
```

- 背景の `-` は、白紙。操作の `-` は、標準入力。`echo '{...}' | $SN render shot.png - -o out.png`。
- 成功すると、標準出力に `{"path","width","height","clamped","skipped"}`。**出力の PNG を、画像として読んで、位置・文字の重なりを確かめること。**
- **座標を、画像のどこに合わせるか**：`--size` を、背景画像の**ピクセル数**（幅x高さ。どちらも偶数、960x640 以上、長辺 8192 まで）にすると、背景が、キャンバスをちょうど埋める。このとき、**操作の座標の 1 pt が、画像の 2 ピクセル**（`x_pt = 画像の x ピクセル ÷ 2`）。出力の PNG も、画像と同じピクセル数になる。
  - 例：2560x1440 px のスクリーンショットの、画像上の (1000, 600) px を囲む → `--size 2560x1440` で、`x=500, y=300`（pt）。
  - レティナの画像（DPI が 144）でも、72 dpi の画像でも、`--size` を画素数に合わせれば、上のとおり。
  - `--size` を省くと、キャンバスは 960x640 px（480x320 pt）。画像は、収まるよう縮小され、中央に置かれる（拡大はしない）。画像とキャンバスの縦横比が違うと、周りに余白ができる。
  - 画像が 960x640 px より小さいと、`--size` を画素数に合わせられない（最小に満たない）。画像は、キャンバスの中央に、自然な大きさ（pt）で置かれ、周りに余白ができる。余白を含めて、キャンバスの座標で指定する。
- `--transparent`：余白（白紙の背景、背景画像の外）を透明にする。
- 画像ビューア（`read` など）は、大きな画像を縮めて見せることがある（「倍率」が示される）。位置を測るときは、見えた座標に倍率を掛けて実ピクセルにし、2 で割って pt にする。同じ出力パスに書き直したあと、ビューアが古い画像を見せることがある。気になるときは、新しい名前で出す。

## 常駐中のキャンバスを操作する

```sh
$SN draw ops.json     # または  echo '{...}' | $SN draw -
$SN get
$SN export
$SN clear
```

- `draw` の成功：`{"added":N,"clamped":[...],"skipped":[...]}`。**1 回の `draw` は、人の取り消し 1 回（Cmd+Z）で、まとめて戻る。** 足した要素は、手前に重なる。
- `get`：`{"canvas":{"width","height"},"background":{"x","y","w","h"}|null,"editing":bool,"items":[...]}`。`items` は、重なり順（0 が奥）で、操作の JSON と同じ形に `index` を足したもの。画像の要素は `path` を持たず、位置と大きさだけ。`background` の枠は、`draw` の座標（pt）と同じ系。**背景の画像のどこに足すかは、`get` の `background` で決める。**
- `editing: true` は、人が、文字を入力中か、ドラッグ中。**それでも `draw`・`clear`・`export` は動き、人の入力は壊れない**（入力中の文字は、確定すると、足した要素の上に重なる）。`get`・`export` の中身は、**確定済みのもの**だけ（入力中の文字は、まだ入らない）。
- `export`：確定済みの内容を PNG に書き出して、`{"path":"/tmp/shortnote/note-….png"}`。変更がなければ、前回と同じパス。
- `clear`：`{"cleared":true|false}`。
- `draw` は、ウィンドウを前面へ出すが、フォーカス（キーボードの入力先）は奪わない。
- `get`・`export` は、キャンバスを変えない（何度呼んでもよい）。`get` の色は、大文字の `#RRGGBB` に正規化され、省いた `size` は、既定値（4）が入る。数は、小数 3 桁に丸められる。
- `export` の PNG は、キャンバスの pt の 2 倍のピクセル（480x320 pt なら 960x640 px）。
- `draw` の返事は、アプリを起動したかどうかを教えない。起動した直後でも、普通に成功する。

## エラーと終了コード

標準エラーに `{"error":{"code":"…","message":"…","op":N}}`（`op` は操作の問題のときだけ）。

| 終了コード | `code` | 意味と、すること |
|---|---|---|
| 0 | — | 成功 |
| 1 | `invalid_ops` | 操作の JSON が不正。`message` と `op` を読んで直す（何も適用されていない） |
| 2 | `usage` | 引数の誤り。`message` の使い方を見る |
| 3 | `unreachable` | アプリに届かない。`get`・`export`・`clear` は、アプリが動いていないと届かない（人に、起動を頼む）。`draw` でも届かないときは、古い版が動いているのかもしれない（人に、ShortNote を終了して起動し直すよう頼む） |
| 4 | `io` | ファイルを読めない・書けない（`image` の画像、背景、出力先、操作の JSON のファイル） |

## 気をつけること

- 相対パスの `image` は、CLI を呼んだディレクトリからのパス。`draw` でも、そのまま書いてよい（CLI が絶対パスにする）。ただし、相対パスの画像があると、大きな要求（約 350 KB 以上の、小数の多いもの）は、断られることがある。そのときは、絶対パスで書く。
- サブコマンドと同じ名前の画像ファイルを、アプリで開くときは、`./draw` のように、パスで渡す。
- アプリは、人のキャンバスを操作する。**人が描いたものを、断りなく、消さない**（`clear` の前に、`get` で中身を見て、本当に要るか考える）。
- ネットワークには出ない。通信は、同じユーザーだけが使える Unix ドメインソケット（`~/Library/Application Support/ShortNote/`）だけ。
