# 検証手順と記録

[SPEC.md](../SPEC.md) の受け入れ条件（A01〜A18）を、どう観測し、何をいつ確認し、何が人間の確認待ちかを記す。新しい合格条件は作らない。実施の権限は、ここからは推測せず、依頼で判断する。共通の操作安全・証拠判定は [macOS 共通検証スキル](../.agents/skills/verifying-macos-apps/SKILL.md)、ケースとコマンドの対応は [ShortNote 固有レシピ](../.agents/skills/verifying-shortnote/SKILL.md) に従う。

## 証拠の種類

次を混ぜない。一つの種類の成功を、別の種類の成功として扱わない。

| 種類 | 例 | 何を示すか |
|---|---|---|
| ソース確認 | コードを読んだ | 実装がそう書かれていること。動作は示さない |
| ビルド | `./scripts/build.sh` が成功 | コンパイルとバンドル作成。動作は示さない |
| 単体テスト | `./scripts/test.sh`（Swift Testing）の pass | 画面に依存しない規則の入出力（履歴・サイズの検証・キーの割り当てと振り分け・保存・描画した PNG の画素・書き出し・画像の取り込み）。実ウィンドウ・実入力は示さない |
| 自動の実機観測 | `scripts/native-e2e.swift` の pass | 自分で起動した候補の、実ウィンドウ・実入力・書き出し PNG の画素で観測した範囲 |
| 人間の確認 | ⌃⌥N、筆圧、色選択、他アプリへのドラッグ | ユーザーが実機で見て判断したこと |
| 配布物の検査 | `./scripts/verify-dmg.sh`（ローカル、または CI の中） | DMG の整合・中身・アイコン・版・Universal・署名（`codesign --verify`）の観測。他の Mac での Gatekeeper の実際の挙動は示さない |
| CI の実行 | GitHub Actions の `release` ワークフローの実行（`gh run view`） | GitHub のランナー（macOS）での、ビルド・単体テスト・DMG の検査。実機の操作（native E2E）と人間の確認は含まない |

## 検証の入口

リポジトリのルートで実行する。

```sh
just e2e          # ./scripts/e2e.sh と同じ。ビルドし、bundle ID を変えたコピーで全ケースを実行する
```

単体テストは、`./scripts/test.sh`（`swift test` に、Swift Testing のマクロプラグインのパスを渡す。Command Line Tools だけの環境では、SwiftPM が渡さないため）で実行する。XCTest は使わない（Command Line Tools に含まれない）。

ハーネスを直接実行するときは、bundle ID を変えたコピーを用意して渡す（`scripts/e2e.sh` の中身を参照）：

```sh
/usr/bin/swift scripts/native-e2e.swift "$PWD/build/ShortNoteE2E.app/Contents/MacOS/ShortNote" --artifacts "$PWD/build/native-e2e"
```

- `--artifacts` を省略すると `build/native-e2e/` を使う。実行ごとに一意の `run-<日時>/` を 0700 で作り、`report.json`（0600）と、候補の診断出力、検証用の画像を置く。`build/` は Git 対象外。
- 終了コードは、fail があれば 1、なければ blocked があれば 77、全 pass なら 0。stdout の「今回の report」を読む。部分成功を総合成功へ広げない。
- 実行中は、**マウスとキーボードに触れない**。ハーネスが物理ポインタとキーを使う。実行中は、ハーネスが起動した候補が一時的に前面になる。終了時に、前面だったアプリへ戻し、クリップボードの文字列を元に戻す（クリップボードの画像などの非文字データは戻らない）。
- 前提：自分の console セッション、画面ロックなし、ディスプレイが起きている、そして実行元（ターミナルなど）に Accessibility・画面収録・イベント送信が許可されていること。SDK の非プロンプト確認で事前に読み、足りなければ blocked にして、必要な許可を依頼する（[手順](../.agents/skills/verifying-macos-apps/references/preflight-and-permissions.md)）。AI が OS の許可設定を変えない。
- **常駐中の ShortNote と同じ bundle ID では実行しない。** 起動した候補が、常駐中のインスタンスへ転送されて出てこない（C1 が fail になる）うえ、保存したキャンバスのサイズが混ざる。入口の `scripts/e2e.sh`（`just e2e`）は、bundle ID を変えた再署名のコピーを自動で作って実行する。ハーネス単体は、同じ bundle ID の常駐があると、blocked（終了コード 77）で何もせず終了する。残った旧い候補は、起動時刻と実行ファイルを照合して、その PID だけを終了する。

ハーネスは、自分が起動した PID だけを、起動時刻と実行ファイルを照合して終了する。キーは、候補が前面でフォーカスを持つことを確認してから送る。ポインタは、送信位置の最前面のウィンドウが候補のものであることを確認してから送る。確認できなければ入力せず blocked にする。画像は、候補のウィンドウだけをウィンドウ ID で撮る。

### 自動では観測しないもの

次は、ハーネスの範囲外であり、人間の確認か、別の手段が要る。

- **A02**：⌃⌥N。他アプリが前面のままキーを送る形になり、共通スキルの入力安全の規則で、AI は送れない。非アクティブ型パネルのため、ホットキーで出した直後に Cmd+V・文字入力・Cmd+Z が効くかも、この経路でしか確かめられない。
- **A03（色）**：色選択の UI。
- **A08（ドラッグで渡す）**：他アプリ（エージェントの入力欄）へのドラッグ。
- **A09**：ペンタブレットの筆圧。
- **A10**：x86_64 での実行（ビルドに含まれることは `lipo -archs` で確認できるが、実行は未確認）。
- **A11**：起動の速さと常駐時の負荷。
- **A04（文字入力中）**：文字入力中の Cmd+Z・Cmd+V が文字欄へ転送されること（ソース上はそう書かれているが、未観測）。
- **配布物**：DMG の実際の Gatekeeper の挙動（別の Mac で確認する）。
- **A14（⌃⌥N の変更）**：全域ショートカットの再登録。他のアプリが前面のままキーを送る形になり、AI は送れない。登録できなかったときの表示も、他のアプリが同じキーを使っている状況が要る。
- **A14（文字入力中のキー）**：文字入力中に、素のキー（1〜6、`[` `]`）が文字として入ること、日本語入力の変換中にキーが入力システムへ渡ること（`KeyRouter` の単体テストでの確認にとどまる）。

## 人間の確認

確認を依頼するときは、次のように、画面・操作・期待する変化を示す。曖昧な観測は未確認とし、成功にも失敗にも決めつけない。

| 条件 | 操作 | 期待する変化 |
|---|---|---|
| A02 | ターミナルなど別アプリを前面にして ⌃⌥N を押す | ShortNote のウィンドウが最前面に出る。その直後に、キャンバスをクリックして描け、Cmd+V で画像が入り、文字ツールで入力でき、Cmd+Z が効く。Esc で隠れる |
| A09 | ペンタブレットのペンで、軽く・強く押して線を引く | 軽いと細く、強いと太くなる |
| A03（色） | 左上の黒い四角（色選択）をクリックして色を変え、描く・文字を書く | 選んだ色で描かれる |
| A08 | 「ドラッグで渡す」を、コーディングエージェントの入力欄へドラッグして放す | 入力欄に PNG のパスが貼り付き、エージェントが画像を読める |
| A06（日本語） | 文字ツールでクリックし、日本語入力で変換する。変換中の Return は変換の確定。もう一度 Return で文字を確定する | 確定した文字がキャンバスに出て、書き出した PNG に含まれる |
